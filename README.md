## 1. Подсистема «Обслуживание клиентов»

### Документ «Обслуживание клиентов»

Процесс работы с заявками организован следующим образом:

1. Клиент обращается к менеджеру и оставляет заявку на выезд специалиста с описанием проблемы.
2. Менеджер находит свободное время и назначает заявку. При этом телеграм-бот уведомляет специалистов о новой заявке.
3. Специалист в назначенное время проводит работы (в офисе клиента или удалённо).
4. Специалист получает подписанный лист учёта рабочего времени (или его скан/фото), где перечислены выполненные работы и часы к оплате. Этот документ служит подтверждением выполнения работ.
5. Специалист вносит в систему данные о выполненных работах: фактически потраченные часы по каждому виду работ, часы к оплате клиентом и прикрепляет скан/фото листа учёта.

#### Документ вводят специалисты и менеджеры. Для работы созданы предопределённые профили пользователей: «BKM_Специалист» и «BKM_Менеджер по обслуживанию».

#### Документ «Реализация товаров и услуг»

В документ добавлена возможность выбора договора с видом «абонентская плата». Реализовано автоматическое заполнение документа суммой ежемесячной абонентской платы и суммой за выполненные за месяц работы на основании данных из документов «Обслуживание клиентов». Из документа печатается акт об оказанных услугах.

#### Документ использует бухгалтер. Для работы создан предопределённый профиль пользователя «BKM_Бухгалтер».

### Обработка «Массовое создание документов Реализация товаров и услуг»

В начале месяца бухгалтер формирует акты по всем абонентским договорам. Этот процесс автоматизирован.

#### Обработку использует бухгалтер. Создана роль «BKM_Массовое создание документов Реализации», подключённая к профилю «BKM_Бухгалтер».

## 2. Подсистема «Расчёт управленческой зарплаты»

На предприятии работают две категории сотрудников: специалисты и административный персонал.  
- **Специалисты** получают минимальный оклад + процент от выполненных работ.  
- **Административный персонал** получает оклад.  
- Любому сотруднику может быть назначена разовая фиксированная премия.  
- Удерживается НДФЛ (13%).

### Документы для расчёта зарплаты:
- «Начисление заработной платы»
- «Начисление фиксированной премии»

### Планирование отпусков

Механизм позволяет составить график отпусков (данные вносятся в начале года).

### Контроль заполнения графиков отпусков

Для визуального контроля пересечений отпусков реализована проверка. При нажатии кнопки «Анализ графика» открывается диаграмма Ганта с информацией по каждому сотруднику.

#### Для работы с подсистемой создан предопределённый профиль пользователя «BKM_Кадровик-расчетчик».

## 3. Отчёты

### Выработка специалистов
Отчёт показывает, сколько часов отработал специалист за выбранный период и какая сумма ему начислена в виде процента от выплат клиента.

### Анализ выставленных актов
Отчёт содержит информацию о клиентах, договорах и суммах, подлежащих выставлению клиентам на основании документов «Обслуживание».

### Расчёты с сотрудниками
Отчёт показывает начисленные и выплаченные суммы каждому сотруднику за период, а также задолженность на начало и конец периода.

### Расход запланированных отпусков
Отчёт за конкретный год показывает, сколько дней отпуска запланировано у сотрудника и сколько дней фактически использовано.

## 4. Подсистема «ДобавленныеОбъекты»

Включает все объекты, созданные в процессе доработки. Доступна только администратору.

# Инструкция по начальной настройке и эксплуатации

## При первом запуске необходимо настроить дополнительный функционал

### Настройки выполняются в режиме «1С:Предприятие»:

1. Создать пользователя с правами Администратор (профиль «Администратор»).
2. Создать пользователей с профилями: «BKM_Бухгалтер», «BKM_Кадровик-расчетчик», «BKM_Специалист», «BKM_Менеджер по обслуживанию».

### Подсистема «Обслуживание клиентов»

1. В режиме администратора настроить.
2. Настроить регламентное задание для отправки сообщений телеграм-боту.
3. Заполнить константы «BKM_ТокенУправленияТБотом» и «BKM_ИдентификаторГруппыОповещения» данными от телеграм-бота.
4. Создать (или выбрать существующую) номенклатуру с видом «Услуги» для отображения в актах клиентам. Рекомендуется: «Абонентская плата» и «Работы специалиста».  
   Заполнить константы «BKM_НоменклатураАбонентскаяПлата» и «BKM_НоменклатураРаботыСпециалиста».

### Перед первым использованием подсистемы «Обслуживание клиентов»

Кадровику-расчётчику необходимо:

1. Заполнить справочник «BKM_Сотрудники» (фамилии сотрудников).
2. Заполнить регистр сведений «УсловияОплатыСотрудников» (поле «Процент от выполненных работ»). Остальные поля можно заполнить позже.

### Перед первым использованием подсистемы «Расчёт зарплаты»

1. Заполнить справочник «Графики работ» (например, «Пятидневка», «Шестидневка»). Для отпуска есть предопределённая запись — «Отпуск календарные дни».
2. С помощью обработки «Заполнение графиков работ» заполнить график. В поле «Выходные дни» указать номера выходных дней недели цифрами подряд (например, для пятидневки — «67»).
3. Кадровику-расчётчику дополнить регистр «УсловияОплатыСотрудников» — поля «График работы» и «Оклад».
4. В разделе «Сервис» назначить график работ для отпуска (должны учитываться все дни).

## Автотесты реализованы с помощью Vanessa Automation

#### Условия для успешного прохождения тестов

1. Автотесты запускаются на прилагаемой [базе данных]((https://cloud.mail.ru/public/dnok/tSL6LpYQc)). В ней настроены предопределённые данные и заполнены справочники тестовыми данными.
2. Перед запуском автотеста клиент-тест должен быть закрыт.
3. Тесты должны запускаться в строгой последовательности:
   - 1. `Создание_документов_Обслуживания_клиента.feature`
   - 2. `Закрытие_документа_Обслуживание_клиента.feature`
   - 3. `Массовое_создание_актов.feature`
   - 4. Для последнего теста сохранить файлы «Ноябрь.mxl» и «октябрь.mxl» из репозитория. На закладке «Сервис → Основные» Менеджера тестирования в поле «Каталог проекта» указать путь к папке с этими файлами.
4. После выполнения указанной последовательности тесты можно запускать повторно в любом порядке.
